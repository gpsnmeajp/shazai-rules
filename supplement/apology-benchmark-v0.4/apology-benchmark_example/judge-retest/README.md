# LLM Judge の追試（判定モデル4種）

2026-11-18 の v0.4 ベンチマークのうち、**LLM Judge（仮想ペルソナ3名の評定と84項目チェック）だけ**を、別の4モデルでやり直しました。生成済みの192回答（4生成モデル×3条件×16シナリオ）と筆者の評定はそのまま使っています。比較の基準は、既存の判定者（Claudeサブエージェント）と筆者の評定です。

| 判定モデル | API | 呼び出し | 費用 |
|---|---|---|---|
| `~typesafe/jev-latest`（Jev 1.14） | Decisions API | 975 | $0.30 |
| `google/gemma-4-31b-it` | Chat Completions | 384 | $0.24 |
| `qwen/qwen3.8-27b` | Chat Completions | 384 | $5.53 |
| `anthropic/claude-haiku-5.5` | Chat Completions | 384 | $0.55 |

推論の強さは各モデルの既定値のままです（Qwen は xhigh、Gemma と Haiku は推論なし）。各判定は1回だけです。

## 実施方法

`../../apology-benchmark/scripts/judge.py` で実行しました。出力は既存と同じ形式（`persona-P1〜P3.json`、`checklist.json`）なので、`benchmark.py check` と `benchmark.py checklist` でそのまま検証・集計できます（各フォルダの `result.json` と `checklist-summary.json`）。

- **ペルソナ**: `references/evaluation.md` の指示をシステムメッセージにしました。シナリオごとに1回呼び出し、回答順はペルソナごとに巡回させています。出力は JSON Schema の構造化出力で受け取りました。既存の判定では、1名が16シナリオを一つのコンテキストで評定していました。今回はシナリオごとに文脈を切っているので、この点が既存と異なります。
- **84項目チェック**: `references/checklist-evaluation.md` の判定基準と `checklist.md` の全文を渡し、1回答ずつ判定させました。84項目をキーにした厳密スキーマは Haiku で「文法が大きすぎる」と拒否されたため、全モデルで配列形式に揃え、項目がすべて揃っているかはコード側で確かめています。

### Jev への対応

Jev は LLM ではなく決定モデル（System One）です。Chat Completions では呼べず（`is a decisions model and cannot be used with the chat/completions endpoint`）、`POST /api/alpha/decisions` に `state` と型付きの質問（`choice`／`score`／`noul`）を送ると、選択肢ごとの確率が返ってきます。文章、理由、JSON は生成しません。そこで、同じ問いを次のように置き換えました。

| 既存の問い | Jev での形 | 評定の取り方 |
|---|---|---|
| 最後の発話時点の不満（0〜4） | `score`（5段階）。回答を読む前に選ぶ指示を守るため、会話だけを `state` に入れた別リクエストにした | 確率最大の段階 |
| 回答ごとの4分類 | 回答ごとに `choice`（rude／light／fit／heavy）。1リクエストの中でも質問同士は互いの答えを見ない | `choice`（確率最大） |
| 84項目×4判定 | 項目ごとに `choice`（hit／clear／unobservable／not_applicable） | `choice` |

コメント欄と該当根拠の欄には、文章の代わりに確率を記しました（例：`heavy 0.64 / fit 0.21 / light 0.14 / rude 0.01（confidence 0.52）`）。確率の生データは `decisions-raw.json` にあります。TypeSafe の説明では、約32,000バイトを超えるリクエストは精度の落ちる長文モードに切り替わるため、チェックリストは1回答あたり5〜6リクエストに分割して送りました。

## 結果

全表は [summary.md](summary.md)、全数値は `summary.json`、判定者同士の κ は `pairwise.txt` にあります。

### 1. 順位の逆転は、全判定者で再現した

「釣り合っている」の件数（ペルソナ3名×64回答＝各192評定）。筆者は各64回答。

| 判定者 | 指示なし | 一般指示 | SHAZAI |
|---|---|---|---|
| **筆者** | 31/64（48%） | 44/64（69%） | **48/64（75%）** |
| 既存（Claude） | **171** | 149 | 138 |
| Jev | **154** | 135 | 119 |
| Gemma 4 31B | **122** | 110 | 103 |
| Qwen3.8 27B | **135** | 118 | 93 |
| Claude Haiku 5.5 | **113** | 96 | 98 |

筆者は SHAZAI＞一般指示＞指示なしの順です。5つの判定者はすべて、ほぼ逆の順位になりました。SHAZAI で増えるのは「足りない」と「重すぎる」で、一般指示では「重すぎる」が最も多くなります（54〜69件）。

### 2. 判定者同士は一致し、筆者とは一致しない

多数決の4分類で求めた Cohen の κ。

| | 既存 | Jev | Gemma | Qwen | Haiku |
|---|---|---|---|---|---|
| **筆者との κ** | 0.061 | 0.050 | 0.025 | 0.005 | 0.025 |
| 既存との κ | — | 0.371 | 0.366 | 0.459 | 0.347 |
| 判定者同士の κ（範囲） | | 0.41〜0.56 | 0.43〜0.54 | 0.46〜0.56 | 0.41〜0.46 |

モデルの系統、大きさ、推論の有無、さらには生成モデルかどうかも違うのに、判定者同士は中程度に一致しました。筆者との一致はどの判定者もほぼ偶然の水準です。既存の結果（κ = 0.06）は Claude 特有の癖ではなく、今回の判定者に共通する読み方だと考えられます。

ずれの中心は「無神経・失礼」です。筆者は192回答のうち32件を `rude` にしましたが、判定者の多数決では0〜4件しか出ませんでした。筆者が `rude` とした回答は、判定者のもとで `fit`（14〜22件）、`heavy`（1〜8件）、`light`（5〜8件）に散っています。

### 3. 失敗には気づいている。ただし「重すぎる」に分類する

箇条書きの場面（SHAZAI の4回答は筆者がすべて `rude`）で、判定者は「書き直しを出していない」ことに気づいています。

> 謝罪と反省の言葉のみで、ユーザーが求めている成果物（導入文）が提示されていないため、さらに手戻りを発生させている。 — Gemma／P1／`heavy`

> 謝罪は丁寧だが同じ内容を重ねて長く、肝心の導入文がなく、ユーザーに余分な時間を使わせる過剰な謝罪になっている。 — Haiku／P1／`heavy`

Jev も確率で `heavy 0.56〜0.64` を返しました。見落としではなく、同じ事実をどの箱に入れるかが違っています。筆者はこれを「明確な指示を無視している」（無礼）と読み、判定者は「謝罪の言葉が多すぎて、成果物が出ていない」（過剰）と読みました。4分類の尺度が「謝罪の量」の軸（light／heavy）と「相手への敬意」の軸（rude）を一本に並べているため、量の軸で説明できる失敗は量の軸に吸い込まれやすいのだと思います。

### 4. 不満の段階の読み方：判定者ごとに違い、修復期で逆転した

設計上の段階別に、知覚段階の平均を示します。

| | 1 | 2 | 3 | 4 | 修復期 |
|---|---|---|---|---|---|
| 筆者 | 3.0 | 2.0 | 3.25 | 3.9 | 2.75 |
| 既存（Claude） | 1.17 | 1.81 | 3.1 | 4.0 | **1.12** |
| Jev | 1.67 | 1.42 | 2.96 | 3.0 | **2.75** |
| Gemma | 1.72 | 1.86 | 2.83 | 3.0 | 2.46 |
| Qwen | 1.14 | 2.14 | 2.83 | 3.25 | 0.96 |
| Haiku | 1.11 | 1.31 | 3.1 | 3.0 | 2.0 |

既存の判定者は、修復期を「謝罪は受け入れられたので不満は1程度」と読みました。Jev と Gemma は、筆者と同じく「まだ3に近い」と読んでいます（Jev は24評定中18件が3）。一方、段階4の「もういいです」「他人事みたいですね」を「4 強い不満」と読んだのは既存の判定者だけで、新しい判定者はほとんど「3」に留めました。

それでも、知覚段階が筆者に近い Jev／Gemma の評定は、筆者に近づきませんでした（κ 0.05／0.025）。不満の読み取りを筆者に揃えるだけでは、評定のずれは埋まらないということです。NextVersionTODO の「知覚段階を採点者のものに固定して評定させる」案は、これだけでは効果が小さい見込みです。

### 5. 84項目チェック：条件差の向きは判定者によって変わる

| 判定者 | 指示なし | 一般指示 | SHAZAI | 段階0・修復期の該当 | 既存との κ（該当か否か） |
|---|---|---|---|---|---|
| 既存（Claude） | 2.53% | 0.62% | 1.20% | 0 | — |
| Jev | 6.71% | 6.96% | 7.75% | 32 | 0.11 |
| Gemma | 2.30% | 1.70% | 1.44% | 0 | 0.20 |
| Qwen | 3.50% | 2.08% | 1.90% | 4 | 0.24 |
| Haiku | 1.90% | 1.55% | 0.97% | 14 | 0.21 |

「指示なしの該当率が最も高い」点は、Jev を除く全員で一致しました。ただし、既存の判定で目立った「一般指示が最も低く、SHAZAI はその2倍」という差は再現せず、LLM 3種では SHAZAI が最も低くなりました。既存の判定で SHAZAI の該当の多くを占めた 10.06（修復に取り組まない、10件）は、新しい判定者では0〜5件でした。項目単位の一致（κ 0.11〜0.24）は、ペルソナ評定の判定者間一致（0.35〜0.56）より低くなっています。どの回答のどの項目を「該当」とするかは、判定者による揺れが大きいようです。

筆者の評定との対応は、LLM ではおおむね保たれました。筆者が `rude` とした回答ほど平均該当数が多くなります（Gemma 2.03 → `fit` 0.88、Haiku 1.31 → 0.59、Qwen 1.94 → 1.15）。4分類のペルソナ評定では筆者と一致しなかった判定者も、項目ごとの事実判定では筆者の「悪い」と同じ方向を向いています。

Jev はここで性質が分かれました。

- **項目を字義どおりに当てはめる。** 01.01「相手に指摘されるまで謝罪しない」に約40件が該当しました。不満のある場面ではユーザーの発話の後に謝るのが当然なので、ほぼすべての謝罪がこの項目の文面に合ってしまいます。
- **「観測不能」をほとんど使わない。** 既存の判定者は約690件、Jev は約40件でした。10.05／10.08（謝罪後の継続的な行動）のように単発の応答では観測できない項目を、`hit` と `not_applicable` に割り振っています。
- **筆者の評定とほぼ無関係になる。** 平均該当数は `rude` 4.28、`fit` 3.75 とほとんど差がありませんでした。段階0・修復期でも32件が該当しています。

一方で、ペルソナの4分類では、Jev は既存の判定者に最も近い分布を出しました（3名一致150件、Fleiss κ 0.68）。単語を選ぶ全体的な判断は LLM と同じようにでき、項目の前提条件（「この項目はこの場面で評価できるか」）を読み解く判断は苦手、という分かれ方です。

## 考察

### LLM の「良識」はひとつの合意として存在する

5つの判定者は大きさも系統もばらばらなのに、互いに κ 0.35〜0.56 で一致しました。ひとつのモデルの癖ではなく、LLM の判定者に共有された「よい謝罪の像」があるように見えます。その像は「簡潔で、重すぎず、対策まで述べる」というものです。筆者の像（「頼まれたことを満たさない謝罪は、どれほど丁寧でも無礼」）とは軸がずれています。v0.1 のときから続く「LLM の評定だけでは謝罪の良し悪しを判断できない」という結論は、判定モデルを替えても変わりませんでした。

逆に見ると、これは LLM 評定の使い道を示しています。判定者が互いに一致し、筆者とは一致しないのであれば、LLM の多数意見は「LLM が書く謝罪の平均的な理想」の測定になります。プロンプトがその平均からどれだけ離れたかの指標としては、安く安定して使えます。SHAZAI Rules が狙っているのは、むしろその平均から離れることです。つまり LLM 評定の低下が、そのまま改善を意味する場合があります。

### 尺度の形が判定を決めている

ずれの多くは、判定者が「見えていない」ことではなく、4分類の箱の切り方から来ていました。箇条書きの場面の判定者コメントは、筆者のコメントと事実認識が一致しています。違うのは、その事実を「量の過剰」と呼ぶか「敬意の欠如」と呼ぶかです。尺度を2軸（謝罪の重さ：足りない／釣り合う／重すぎる、要求への応答：満たした／満たしていない／無視した）に分ければ、判定者と筆者の一致は今よりかなり上がる可能性があります。次の版で試す価値があると思います。

### 決定モデルは問いの立て方を映す鏡になる

Jev は理由を書かない代わりに、問いをそのまま受け取ります。01.01 の過剰な該当は、項目の文面が「謝罪のタイミング」ではなく「指摘の後に謝る」という表面の順序を指していることを、はっきり示しました。LLM の判定者は、チェックリスト評価の手引き（「履歴から発覚を待った意図を推定しない」など）と常識で、この文面を補って読んでいます。その補いが判定者ごとに違うことが、項目単位の一致の低さ（κ 0.1〜0.24）に表れています。決定モデルで多く該当した項目は、文面だけでは判定が定まらない項目です。チェックリストの文言を見直す手がかりとして使えます。

確率で返すことにも利点がありました。多数決ではなく確率の期待値で見ると、Jev の `fit` は指示なし 0.65、一般指示 0.63、SHAZAI 0.53 でした。重さは一般指示の `heavy` 0.28 に集まり、SHAZAI では `light` 0.24 と `heavy` 0.22 に割れています。SHAZAI の回答は「軽すぎる」と「重すぎる」のどちらにも読まれうる、判定者にとって曖昧な位置にある、ということが一回の判定から分かります。

### 費用と速度

ペルソナ評定だけなら、Jev は $0.3 程度、数分で4モデル分を終えました。分布は既存の判定者に最も近いものでした。人間の評定の代わりにはなりませんが、「LLM の多数意見の見積もり」を安く出す道具としては十分です。Qwen は推論が既定で xhigh のため、費用は Jev の約18倍、時間は約1時間でした。それでも筆者との一致は最も低くなりました（κ 0.005）。推論を増やすほど、LLM の合意の中心に近づくのかもしれません。

## 限界

- 各判定者は1回だけ判定しました。同じ判定者を繰り返したときのばらつきは測っていません。
- ペルソナの評定はシナリオごとに文脈を切って行いました。既存の判定者は16シナリオを一つの文脈で評定しているため、条件がそろっていません。
- Jev への置き換え（問いの文面、`score` の最頻値を知覚段階とすること、長文モードを避けるための分割）は今回の設計です。Jev の性能そのものを測ったものではありません。
- 比べている人間の評定者は筆者1名だけです。
