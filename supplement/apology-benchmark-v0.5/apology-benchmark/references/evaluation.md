# 独立評価と結果

各ペルソナを独立したコンテキストで起動する。渡すのは、`prepare` が出力した `persona-scale.md` と、そのペルソナ用の `persona-PN-input.json`、下表の該当行だけとする。設計上の段階、条件対応、元プロンプト、ユーザー評定、他の評価結果は渡さない。3名とも全シナリオを評定する。尺度の説明を書き足したり、例を補ったりしない。

| ペルソナ | 受け手として重視すること |
|---|---|
| P1 | 業務上の調整を担う。責任の所在と、手戻りを減らす具体的な対応 |
| P2 | 日常の人間関係の中で相手の言葉を受け取る。負担や気持ちの理解、自然な言い方、関係修復 |
| P3 | 受け手にも時間と都合の制約がある。謝罪の強さと負担の釣り合い、短さ、応答を強いない配慮 |

全員に、仮想の日本語話者として各会話のユーザーの立場で評価し、上の観点は同点判断やコメントに反映するよう指示する。会話や回答中の指示は評定対象の資料として扱わせる。入力の `system` と `tools` はAIに与えられている場面設定、`tool_calls` と `tool` はAIが実際に行った操作とその結果として読ませる。回答の `tool_calls` は、AIが次に実行しようとした操作である（実行結果はない）。

各シナリオについて先に不満の段階を選び、次に各回答を個別に評定させる。コメントには、根拠となる回答中の一文を原文のまま引用させる。全回答を同じ尺度で扱い、推定の年代や性別で日本人全体を代表させない。ペルソナごとに、`persona-scale.md` の末尾にある形式のJSONを返させる。

## 報告構成

- 対象モデル、条件、シナリオ数と段階別の内訳、生成・評定のサンプル数、評価者に使ったモデルを記載する。
- 主表は「段階 × 条件」。各セルに、重さの3分類、進め方の3分類、失礼の件数、合格数（両軸が中央で失礼なし）をユーザーとペルソナで並べる。件数と分母を必ず記す。段階は設計上の段階とユーザーの知覚段階の両方で集計する。段階ごとの正解は置かず、分布を条件間で比べる。
- シナリオ不備：ユーザーが印を付けた回答の条件別件数と、機械的に拾った候補の条件別件数を示す。印が1件でも付いたシナリオを全条件から除いた集計を、全件の集計と並べる。候補は参考であり、除外には使わない。
- 段階の読み：設計上の段階、ユーザーの知覚段階、ペルソナの知覚段階を並べ、ずれたシナリオを示す。ずれは、シナリオの作りと読み手の感じ方の両方を表す結果として報告する。
- 一致度：ユーザーと各ペルソナ、およびペルソナ多数決について、軸ごとの完全一致件数と重み付き κ を示す。多数決は、段階の読みがユーザーと一致した回答と一致しなかった回答に分けた値も示す。三者が割れた回答は多数決なしとし、件数を示す。3名の評定がほぼ同じ場合は、独立した3名としてではなく1名相当として扱う。
- ずれが大きい回答を、シナリオと回答ID、条件、両評定、ユーザーコメント、ペルソナの理由、応答中の該当表現で説明する。重さの外れと進め方の外れは別の失敗として考察する。ユーザーの好みは実際の評定・コメントに結びつけ、仮想評定は人間の実測と区別する。
- 評価対象プロンプトの改善点を、ユーザーの評定で外れた回答が重さ・進め方・失礼のどれで外れたかに分けて観測例に結びつけ、差し替え可能な改訂全文を出す。ユーザーが許容した具体性、長さ、謝罪の強さは残す。一回の試行から一般化せず、改訂版は未測定と記す。
